# 가상 데이터 시범 배포

실제 데이터는 클라우드 인증/역할별 접근/백업 복구 검증 후 이전한다. 로컬 DB는 외부 사용자의 브라우저에서 접근할 수 없다.

1. 소유자의 Supabase·Cloudflare 프로젝트 확인. 무료 범위와 계정 연결을 확인한다.
2. 개발/시범 DB를 운영 DB와 분리한다. migrations만 적용하고 실제 DB에 seed/reset을 실행하지 않는다.
3. 클라우드 초대 가입/계정 복구/동명동일생일 처리 정책을 확정한다. 현재 내부 이메일 매핑 가입 방식은 로컬 검증용이며 이메일 확인을 요구하는 클라우드에서는 그대로 동작하지 않는다.
4. Cloudflare 빌드 명령 `pnpm build:staging`, 출력 `dist`. 환경변수는 `.env.example`의 공개 URL/공개 키만 설정한다. 서비스 역할 키는 브라우저 빌드에 절대 사용하지 않는다.
5. 테스트 계정은 시범 DB에만 만든다. 공개 저장소에 기재된 공통 비밀번호를 외부 DB에서 사용하지 않는다.
6. 배포된 URL에서 모든 역할의 거부/허용, 새로고침, 초대, 로그아웃, 예약 전환을 확인한다.
7. 백업 파일 보호·복구 리허설, 기록 보존 정책, 실제 명단 중복 정리 후 운영 이전한다.

현재 상태: 프로젝트 연결 대기. 배포용 빌드에 로컬 URL·서비스 키를 넣으면 실패하도록 검사를 추가했다. 이것만으로 운영 보안 검증이 완료되는 것은 아니다.
