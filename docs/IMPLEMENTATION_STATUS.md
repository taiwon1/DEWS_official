# 구현 현황

기준: 2026-11-13. **로컬 기능 검증 단계이며 실제 운영 준비 완료는 아니다.** 과거 UI 시연 단계 안내는 이 문서로 대체한다.

## 구현·검증 완료

- 실제 Supabase 로그인, 유지 세션, 로그아웃, 본인 비밀번호 변경, 48시간 단일 사용 초대 링크.
- 150명 가상 인원, 19개 역할별 계정. 중복 역할과 부리더 포함.
- 서버에서 직책·담당 그룹 검사. 직접 테이블 접근 차단 및 RLS 활성화. 독자 응답에서 게시글/댓글 작성자 ID 제외.
- 신규 인원 등록, 1~4주차별 교육 이수, 첫 방문 6개월 자격 검사, 장결·제적·복귀·별도 권리 회복 및 이력.
- 같은 페이지에서 예배·소그룹 출석 체크, 명시적 확정, 미확정 구분, 동시 수정 충돌 방지, 과거 소속 기준 명단.
- 2/4/26주 결석 확인, 리더 기록·목회자 공유/비공개 기록, 기수별 인계, 다음 연락일과 완료 기록.
- 교육 완료자 편성, 제외/고정 배정, 이전 고정 설정 불러오기, 최근 6개월 출석률 균형 무작위, 직전 그룹 중복 표시, 수동 이동, 리더/부리더 지정, 예약/취소, 활동 종료와 추가 배정.
- 예약 전환을 DB 트랜잭션으로 처리. 실패 시 부분 적용 없이 되돌림. 후임 리더 기록 접근과 이전 리더 접근 종료 검증.
- 행사 생성·수정·포스터 첨부(A4 비율), 월별 캘린더, 동아리 생성·수정.
- 익명 공개/비공개 게시글과 댓글, 검색·필터. 비공개는 작성자·임원·목회자만 읽고 댓글 작성 가능.

## 검증 근거

- 빌드 성공, 단위 테스트 17개 통과.
- 실제 인증/DB 통합 시나리오 18개 통과. 19개 계정 로그인, 권한 우회 거부, 초대 재사용 차단, 비밀번호 변경 후 재로그인 포함.
- 브라우저에서 일반 청년 로그인, 권한별 메뉴 제한, 게시글 열람과 익명 댓글 저장 확인.
- 전체 역할의 모든 화면을 모바일에서 직접 클릭한 전수 검증은 아직 하지 않았다. 자동 테스트 결과와 UI 전수 검증을 혼동하지 않는다.
- 상세 자동 결과는 TEST_RESULTS.md, 사용자 검토 순서는 TEST_GUIDE.md 참조.

## 임시 구현 기준 — 운영 승인 필요

- 최초 정회원 편입은 자격 조건 확인 후 목회자 승인으로 구현. 자동 편입 여부는 미확정이다.
- 공개 게시판은 로그인한 공동체 공개다. 외부 비로그인 공개가 아니다.
- 출석률은 확인 가능한 주만 분모로 사용하며 미확정 주는 결석으로 간주하지 않는다. 모임 취소·가중치·기록 부족 기준은 확정 필요. 편성 시 자료 없는 사람은 임시 50%로 계산한다.
- 장결·제적은 자동 편성에서 제외한다. 복귀 시 별도 상태 변경 후 편성한다.
- 예약은 한국시간 기준이며 cron이 매분 확인한다. 지정일 0시 이후 첫 실행에 적용되므로 초 단위 정시 실행 보장은 없다. Docker가 꺼져 있으면 재실행 후 처리한다.
- 포스터는 로컬 시범용으로 1MB 이하 이미지 데이터를 DB에 저장한다. 운영에는 별도 파일 저장소·정책 필요.
- 사용자명은 내부 인증 식별자로 변환한다. 로컬은 이메일 확인을 끈 환경이다. 동명이인·생일 중복, 비밀번호 분실 복구, 운영 가입 제한은 운영 전 확정·보강해야 한다.
- 전체 관리자 역할 자체에 목회자 개인정보 우회 권한을 주지 않았다. 역할 부여/회수 관리 UI 및 최종 관리자 정책은 미정이다.

## 남은 운영 작업

1. 역할별 사용자 화면 검토와 모바일 전수 검증, 필요한 수정.
2. 미확정 정책: 기록 보존·삭제, 최초 편입 승인, 계정 중복/복구, 출석률 분모와 취소, 게시글/댓글 수정·삭제·신고.
3. 실제 시트 형식 확인과 이전 리허설, 중복 인원 정리, 백업 복구 검증.
4. 운영 인증 설정·접근제어 재검증, 클라우드 예약 작업과 파일 저장소 구성, 외부 배포.
5. 알림톡·외부 알림·AI 요약·행사 신청 폼은 후속 범위다. 현재 돌봄 알림은 앱 안의 확인 목록이다.

유료 서비스 활성화와 실제 개인정보 업로드는 하지 않았다. 로컬은 Windows에서 실행하며 원격 브랜치는 codex/initial-platform이다.
