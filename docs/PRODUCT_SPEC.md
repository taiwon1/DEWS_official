# DEWS 인원 관리 플랫폼 — 구현 기준 기획서

최종 정리: 2026-11-12 (한국시간)

이 문서는 도원동교회 이슬청년부(DEWS) 플랫폼에 관한 현재 대화의 결정을 통합한다. 2026-11-12 사용자가 코드 구현과 GitHub 연결을 승인했다. 현재 구현 범위와 검증은 docs/IMPLEMENTATION_STATUS.md를 따른다.

## 1. 문서 사용법과 결정 상태

- **확정:** 사용자가 직접 정하거나 명시적으로 수용한 내용. 별도 표시 없는 요구사항은 확정 사항이다.
- **제안:** PM이 제시했으나 명시적으로 확정되지 않은 운영·설계안. 구현 전에 필요한 범위를 확인한다.
- **미정:** 답변이나 정책 결정이 필요하다. 임의의 기본값을 확정 정책처럼 구현하지 않는다.
- 이 문서는 법률 검토나 최종 데이터베이스 설계서가 아니다. 보존·삭제 정책 등은 아직 결정되지 않았다.
- 후속 결정이 생기면 해당 본문과 하단 결정 이력을 함께 업데이트한다.

## 2. 목적, 규모, 현재 운영

- 핵심 목적: 출석 관리 효율화 및 돌봄 대상 누락 방지.
- 관리 대상 약 150명(장결 포함), 목회자 2명, 임원 7명, 소그룹 리더 9명. 역할 겸임이 있다.
- 현재 명단은 구글시트로 관리하며, 목회자가 별도 파일을 관리하기도 한다. 임원이 최종 정보 책임을 맡지만 자료가 분산되어 있다.
- 과거 소그룹 편성 자료는 모두 존재한다. 실제 파일과 형식은 아직 받거나 검증하지 않았다.
- PC 버전 중심으로 배포하되 모바일에서도 사용 가능해야 한다. 누구나 쉽게 입력·조회하는 UI/UX를 중시한다.
- 행사·동아리는 초기에는 소개와 일정만 제공한다. 참가 신청 및 폼은 추후 범위다.

**제안:** 운영 시작 후 공통 인원 정보의 기준 원본을 플랫폼으로 통일한다. 구글시트·목회자 파일을 계속 독립 수정하면 정보 충돌이 생긴다. 이전 자료의 우선순위와 병합 방식은 미정이다.

## 3. 인원 분류: 서로 혼동하면 안 되는 축

다음은 동작을 설명하기 위한 개념 구분이며 최종 DB 필드나 enum은 아니다.

1. 회원 분류: 새가족 / 정회원.
2. 재적 관련 상태: 재적 포함 / 새가족으로 재적 제외 / 장결 / 제적.
3. 교육 진행: 등록 희망 전 / 교육 중 / 1~4주차 모두 이수.
4. 담당 소속: 새가족반 / 일반 소그룹 / 배정 대기 등.
5. 시스템 역할·직책: 목회자, 임원 직책, 소그룹 리더, 부리더, 새가족반 담당자 등. 겸임 가능.

### 3.1 정회원과 재적

**최초 정회원 자격 및 재적 편입 조건 = 첫 방문일부터 6개월 경과 AND 1~4주차 교육 모두 이수.**

| 상황 | 분류·재적 | 일반 소그룹 배정 | 투표권 |
|---|---|---|---|
| 교육 미완료 | 새가족, 재적 제외 | 불가 | 없음 |
| 교육 완료 + 첫 방문 후 6개월 미경과 | 새가족, 재적 제외 | 가능 | 없음 |
| 교육 완료 + 첫 방문 후 6개월 경과 | 정회원·재적 편입 조건 충족 | 가능 | 있음 |
| 장결 또는 제적 | 별도 목록, 재적 제외 | 정기 편성 제외 방향은 제안 | 없음 |

- 교육 완료 후 6개월을 기다리는 규칙이 아니다.
- 첫 방문 후 6개월이 지나도 교육 미완료면 정회원이 아니다.
- 조건 충족 시 최초 편입을 자동 처리할지 승인 절차를 둘지는 미정이다. 복귀자의 자격 회복 승인과 구분한다.
- 첫 방문일을 기준으로 사용한다. 어떤 만남을 최초 방문으로 인정할지와 6개월의 정확한 날짜 연산은 미정이다.

### 3.2 청년부 구분

- 생일 기준 만 나이가 아니라 출생연도로 구분하고 매년 1월 1일 기준을 적용한다.
- 사용자가 준 기준: 2026년에는 2007년생부터 들어온다. 1청년부는 20~26세, 이후는 2청년부.
- 위 기준의 계산 해석: 기준 연도 - 출생연도 + 1. 2026년 1청년부는 2001~2007년생, 2청년부는 2000년생 및 이전.
- **제안:** 청년부 연령 구분 변경과 소그룹 변경은 별개로 처리하고 과거 이력은 당시 기준으로 유지한다.
- 20세 미만 예외 등록, 출생연도 미상 처리, 연령 구분의 자동 전환 세부 사항은 미정이다.

## 4. 역할 및 권한

### 4.1 역할 목록

- 전체 관리자: 사용자의 최초 설명은 실제 기능 테스트 담당. 운영 데이터 접근 범위는 미정.
- 목회자: 2명 모두 목회자 기록을 공유한다.
- 임원 7개 직책: 2청년부 회장, 2청년부 총무, 1청년부 회장, 1청년부 총무, PD, 회계, 서기.
- 2청년부 총무는 1·2청년부를 포함한 모든 청년의 소그룹 관리 담당이다.
- 소그룹 리더, 소그룹 부리더.
- 새가족반 담당자: 초기의 리더/팀원 구분은 폐기. 모두 동일한 새가족반 리더 권한을 갖는다.
- 일반 청년.

### 4.2 확정 권한과 제한

| 역할 | 출석 | 리더 특이사항·기도제목 | 목회자 담당자 공유 기록 | 목회자 비공개 기록 |
|---|---|---|---|---|
| 목회자 | 돌봄을 위한 전체 현황 확인; 입력·수정 범위 미정 | 전체 열람 | 전체 열람·작성 | 전체 열람·작성 |
| 소그룹 리더 | 담당 그룹 입력·확정 | 담당 그룹 열람·작성 | 담당 그룹 열람 | 불가 |
| 부리더 | 담당 그룹 출석 관리만 | 불가 | 불가 | 불가 |
| 2청년부 총무 | 전체 소그룹 수정 가능 | 전체 열람 | 총무 직책만으로는 부여하지 않는 제안 | 불가 |
| 새가족반 담당자 | 새가족 출석·교육 기록 관리 방향; 예배 입력 범위 최종 확인 필요 | 담당 새가족 열람·작성 | 담당 새가족 열람 | 불가 |
| 그 외 임원 | 행사 관리; 소그룹 출석 수정 권한 없음 | 임원 직책만으로 권한 없음 | 임원 직책만으로 권한 없음 | 불가 |
| 일반 청년 | 관리 권한 없음 | 타인 기록 열람 불가 | 불가 | 불가 |

- 일반 청년: 본인 정보 및 행사·동아리 정보, 본인 소그룹원 이름 조회. 본인 정보 수정 범위와 본인 돌봄 기록 열람 여부는 미정.
- 연락처는 임원·목회자에게만 공개한다. 리더·부리더·새가족반 역할만으로 연락처 열람 권한이 생기지 않는다.
- 새가족 인원 등록은 목회자 또는 새가족반 담당자가 한다. 일반 청년의 직접 등록은 허용된 요구사항이 아니다.
- 소그룹 편성·배정은 2청년부 총무가 입력한다.
- 소그룹 개편 및 활동 종료 권한자는 목회자 또는 2청년부 총무다. 목회자의 명단 편집 권한까지 포함하는지는 미정.
- 장결 확정, 제적 전환, 재적 복귀, 정회원 자격 회복은 목회자 권한이다.
- 역할 겸임 시 허용 권한을 결합하되 담당 범위가 확대되지 않도록 한다. 예: 총무 겸 리더의 리더 전용 권한은 자기 그룹에만 적용.

**제안:** 테스트는 가상 데이터로 분리하고 전체 관리자에게 민감 기록 열람을 무조건 허용하지 않는다. 사용자별 자유 권한 편집보다 직책·담당 그룹 기반으로 관리한다.

## 5. 새가족 등록과 교육

- 등록을 희망하는 순간 교육 중으로 전환한다.
- 1·2·3·4주차는 서로 다른 강의이며 모두 이수해야 한다. 연속 4주일 필요는 없다.
- 결석·2부 행사로 교육이 밀릴 수 있다. 단순히 4주가 지났다고 완료 처리하지 않는다.
- 새가족반 담당자 누구나 교육 이수를 기록할 수 있다. 초기의 담당 주차별 권한 제한은 최종 요구가 아니다.
- 교육 참석은 주일예배·소그룹 출석과 별도로 기록한다.
- 교육 미완료자는 새가족반에서 관리한다. 교육 완료 후 일반 소그룹 배정이 가능하다.
- 교육 완료여도 첫 방문 후 6개월 미경과면 새가족 분류이고 재적에는 포함하지 않는다.

**제안:** 이수 주차·실제 교육일·기록자를 보존하고 동일 주차 중복으로 완료 처리하지 않는다. 교육 완료 후 미배정자는 배정 대기로 표시하며 실제 인계 전까지 새가족반이 책임을 유지한다. 교육 출석만으로 예배 출석을 자동 인정하지 않는다.

## 6. 출석과 돌봄

### 6.1 입력

- 주일예배와 소그룹 모임 출석은 한 페이지의 같은 명단에서 두 체크박스 열로 입력한다. 기록은 모임별로 분리하며 리더가 입력하고 부리더가 대신할 수 있다. 탭을 오가지 않는다.
- 날짜와 모임을 선택한 뒤 참석할 소그룹원들을 다중 선택하고 출석 확정한다.
- 확정 시 선택된 사람은 출석, 나머지는 결석. 확정 전에는 미입력으로 둔다.
- 한 사람을 체크했다는 이유로 나머지를 자동 결석 처리하는 초기 제안은 폐기됐다.
- 2청년부 총무는 전체 소그룹 출석을 수정할 수 있다.
- 행사는 임원이 관리한다. 초기 행사 참가 신청·출석 상세 화면은 아직 범위가 확정되지 않았다.

**제안:** 입력 도중 임시 저장, 확정 전 출석·결석 인원 요약, 확정 후 수정 이력, 모임별 독립 확정. 수정 마감·과거 날짜 수정·모임 취소·전체 결석 및 동시 편집 처리는 미정.

### 6.2 연속 결석과 알림

- 한 주에 주일예배 또는 소그룹 중 하나라도 참석하면 출석으로 인정한다.
- 2주 연속 결석: 리더 확인.
- 4주 연속 결석: 목회자 확인.
- 26주 연속 결석: 장결 후보를 표시하고 목회자가 확정한다.
- 군입대·유학도 26주 장결 규칙에 포함한다.
- 장결과 제적은 별도 목록으로 관리한다.

**제안:** 미확정·과거 자료 없음은 결석으로 단정하지 않고 기록 확인 대상으로 표시한다. 알려진 부재 사유에 따라 반복 알림을 유예할 수 있게 하고, 돌봄 건에 담당자·다음 연락일·완료 상태를 둔다. 주간 경계, 모임이 없던 주, 반복 알림 주기, 채널, 유예 정책은 미정이다.

### 6.3 장결·제적·복귀

- 장결 확정 시 재적에서 제외되고 회원 권리를 잃는다.
- 목회자가 장결자를 제적시킬 수 있다. 제적 후에도 관련 정보는 보존한다.
- 목회자가 재적 복귀를 처리하고 사유를 남긴다.
- 복귀자의 정회원 자격 회복은 별도 목회자 승인이다. 자동 회복하지 않는다.
- 언제 재적에 들어왔고 언제 정회원이 됐는지, 장결·제적·복귀·회복을 타임라인으로 남긴다.
- 복귀 조건은 개인별로 다를 수 있으므로 현재 단계에서 하나의 자동 공식으로 고정하지 않는다.
- 기록 보존 기간은 미정이며 영구 보존으로 확정한 것이 아니다. 제적과 데이터 삭제는 구분한다.

## 7. 돌봄 기록과 인계

- 기록은 청년 개인에게 귀속하며 작성자와 작성 당시 역할을 구분해 표시한다.
- 리더 작성 특이사항·기도제목과 목회자 작성 기록을 분리한다.
- 목회자 기록은 공유/비공개로 구분한다. 공유 기록은 목회자와 현재 담당 리더 또는 새가족반이 열람한다. 비공개는 목회자만 열람한다.
- **제안 명칭:** '공개' 대신 '담당자 공유'로 표시하여 전체 공개와 혼동하지 않게 한다. 기본값 비공개는 제안이다.
- 리더 교체 및 개인의 그룹 이동 모두 새 담당자에게 기존 리더 기록과 목회자 공유 기록을 인계한다.
- 이전 리더는 담당 종료 후 해당 청년 기록에 접근하지 않는 방향으로 설계한다.
- 기수별로 새 기록을 작성한다. 과거 기수 내용은 필요할 때 열람하며 현재 기록에 무조건 합쳐 넣지 않는다.
- 보존 기간은 추후 결정한다.

**제안:** 미완료 돌봄 업무는 기수 종료로 사라지지 않게 인계한다. 자동 요약은 최초 희망 기능이지만 초기 구현 범위로 확정되지 않았다. 요약을 도입한다면 원문 보존과 작성자 확인이 필요하다.

## 8. 소그룹 편성 지원

### 8.1 담당자와 대상

- 담당자는 2청년부 총무다. '2청년부 리더'라는 표현은 총무로 정정됐다.
- 기본 대상은 **1~4주차 교육 완료자**다. 재적 인원만 불러오는 초기 기준은 폐기됐다.
- 교육 완료·기간 미충족 새가족도 배정 대상이다. 교육 미완료자는 제외한다.
- 시작 전에 총무가 대상자를 제외할 수 있다. 편성 제외는 회원 자격이나 재적 상태 변경이 아니다.
- **제안:** 교육을 과거 이수했어도 장결·제적자는 기본 편성에서 제외한다. 복귀 시 포함 기준은 확인한다.

### 8.2 편성 순서

1. 교육 완료 대상자를 불러오고 제외 대상을 확인한다.
2. 소그룹을 만들고 그룹별 리더를 지정한다. 편성 시작 시 부리더 지정은 필수 요구가 아니다.
3. 별도 배정할 사람·조건을 입력한다. 이전 개편의 별도 배정 설정을 불러올 수 있어야 한다.
4. 최근 6개월 출석률을 기준으로 균형을 맞춰 무작위 초안을 만든다.
5. 직전 소그룹이 같았던 인원만 표시한다. 그보다 오래된 중복 최적화는 현재 범위가 아니다.
6. 총무가 직접 이동·교체하여 최종 명단을 정한다. 희망사항은 담당자만 입력한다.
7. 최종 명단 확인 후 적용일을 입력하고 자동 전환을 예약한다.

- 여러 사람이 담당자 화면을 함께 보면서 편성할 예정이다.
- 과거 소그룹 자료가 있으므로 직전 기수 중복 판단에 활용한다. 데이터 가져오기 방식은 미정이다.
- 자유 서술 특이사항을 자동 해석해서 편성하는 요구는 확정되지 않았다.

**제안:** 그룹별 인원수와 출석률 구간 분포를 함께 고려한다. 이전 별도 배정 조건은 유지 여부를 재확인한다. 배정 고정 후 나머지만 재추첨할 수 있게 한다. 조건 충돌을 숨기지 않고 표시한다.

### 8.3 출석률 계산의 확정 범위

- 기간은 최근 6개월이다.
- **제안:** 주일예배 또는 소그룹에 참석한 주를 출석으로 계산하고, 그룹별 인원도 균형화한다.
- 정확한 분모, 미확정 주 제외 방식, 신규 청년의 관찰 기간, 기록 부족 기준, 모임 취소 처리와 예배/소그룹 가중치는 아직 미정이다.
- **제안:** 계산 기준일과 사용 데이터를 초안 생성 시 고정한다. 예약 중 새 출석이 입력됐다고 명단을 자동 변경하지 않는다.

### 8.4 편성 화면의 개인정보

**제안:** 함께 보는 편성 화면은 이름·출석률·직전 그룹·배정 결과 위주로 표시한다. 특이사항·기도제목 원문과 분리 배정 상세 사유는 기본적으로 숨긴다. 담당자의 열람 권한이 동석자 모두의 열람 권한을 뜻하지 않는다.

## 9. 기수와 예약 전환, 추가 배정

- 그룹은 고정 월 단위가 아니라 실제 시작·종료일로 관리한다. `2026-1`, `2026-2` 같은 기수 표시는 사용할 수 있다.
- 개편 월은 유동적이다. 반드시 1월/7월 또는 매월 1일일 필요가 없다.
- 예약 적용 시각은 **지정일 한국시간 0시**다.
- 목회자 또는 2청년부 총무가 개편과 활동 종료를 관리한다. 여러 번 확인하되 다중 승인자는 필요 없다.
- 최종 명단을 정한 후 적용일을 입력하고 예약한다.
- 개편 이후에도 교육 완료자를 현재 소그룹에 개별 추가 배정할 수 있다. 입력 담당자는 2청년부 총무다.
- 과거 소속과 기록은 보존하고 현재 담당자를 갱신한다.

**제안하는 안전 절차:**
- 작성 중 → 검토 완료 → 예약 확정 → 적용 완료로 구분.
- 기존 기수 운영을 유지하면서 새 편성을 준비.
- 종료·시작 그룹과 이동 인원 미리보기, 누락·중복·리더 미지정 확인, 적용일과 권한 변경 최종 확인.
- 기존 종료와 새 기수 시작·권한 변경·인계를 일관되게 적용하고 일부만 전환되지 않도록 처리.
- 예약 후 수정 시 재확인, 결과·실패 알림, 실행 이력과 복구 수단 마련.
- 개별 추가 배정의 적용일·처리자를 기록하고 배정 전 기간을 새 그룹 결석으로 소급 처리하지 않음.

예약 시점과 적용일 사이의 신규 인원·장결·그룹 이동 충돌, 예약 취소·수정 마감, 종료만 하는 경우, 복구 방법, 부리더 지정 시점은 미정이다.

## 10. 행사·동아리·화면 방향

- 행사 게시판은 포스터 중심 목록으로 구성한다. 포스터 표시 영역은 A4 세로 비율(210:297)을 유지하고 이미지 전체를 잘리지 않게 표시한다.
- 메인 페이지에 월별 행사 캘린더를 제공한다. 기존 민트·청록색 컨셉에 맞춰 작은 행사 표시와 절제된 움직임을 사용한다.
- 행사: 게시판 형태의 안내와 예정 일정. 월별로 보기 쉽게 표시하고 싶다는 요구가 있다.
- 동아리: 어떤 동아리가 있고 언제 활동하는지 소개와 일정 제공.
- 참가 신청·폼은 후속 단계로 보류한다. 회비·정원·결제는 확정 범위가 아니다.
- PC 우선, 모바일 호환. 구체적 화면 디자인은 아직 결정되지 않았다.
- 후속 UI 피드백: 추상적인 홍보 문구 대신 화면·버튼의 실제 기능이 예상되는 직설적인 표현을 사용한다. 영어 장식 문구와 과도한 장식을 줄이고 폰트·크기·여백을 정돈한다.
- 추가 정정: 'AI 티가 나지 않게'는 호버·전환 효과 제거를 의미하지 않는다. 카드 확장과 버튼 반응을 유지하면서 요소 크기·비율·글꼴 위계를 정돈한다. 출석표는 입력을 방해하는 레이아웃 이동 없이 강조 반응만 적용한다.

**제안하는 역할별 첫 화면:**
역할별 세부 첫 화면은 아래 제안 상태다. 다만 로그인 후 권한에 맞는 메뉴·버튼·조회 범위를 제공하고 공통 화면을 재사용하는 방향은 사용자 승인됨. 서버·DB에서도 접근을 검사하며, 가상 계정 미리보기는 실제 인증과 구분한다.
- 리더·부리더: 이번 주 담당 그룹 출석. 부리더에게 돌봄 기록을 노출하지 않음.
- 새가족반: 등록·교육 현황과 확인할 새가족.
- 총무: 전체 입력 현황, 편성·배정과 미배정 인원.
- 목회자: 4주 이상 결석, 연락 예정·미완료, 장결·복귀 검토.
- 일반 청년: 행사·동아리 일정과 본인 소그룹.
- 모바일 출석은 가로 스크롤 없이 명단에서 다중 선택·확정할 수 있도록 설계.

### 10.1 익명 게시판

- 구성원이 제목·내용을 작성하고 공개/비공개를 선택한다.
- 공개 글은 모두 열람. 현재 구현 해석은 로그인한 공동체 구성원 전체이며, 비로그인 인터넷 공개는 별도 확인 전 허용하지 않는다.
- 비공개 글은 작성자 본인, 모든 임원(7개 직책), 목회자만 열람한다. 소그룹 리더·부리더·새가족반 담당자·전체 관리자 직책만으로 별도 열람 권한을 부여하지 않는다.
- 모든 작성자는 익명으로 표시한다. 임원·목회자에게도 이름을 노출하지 않는다. 내 글 식별 표시는 본인에게만 제공한다.
- 권한 확인을 위한 내부 작성자 식별값은 필요하다. 운영 API의 독자 응답에는 작성자 ID를 제외하고 본인 글 여부만 제공하는 설계 방향이다. UI의 익명 표시와 시스템에 작성자 연결 자체가 없는 완전 익명은 다르다.
- 비공개 제목·본문·검색 결과·건수도 허용된 독자에게만 제공한다. 실제 운영에서는 서버·DB에서 먼저 필터링한다.
- 현재 시연의 비공개 기본 선택과 등록 전 범위 재확인은 보수적인 UI 기본값이다.
- 댓글·첨부·수정·삭제·신고·보존 기간·운영자의 익명 해제 권한은 미정이며 이번 구현에 포함하지 않는다. 게시판 권한은 목회자 돌봄 기록의 비공개 규칙을 변경하지 않는다.

## 11. 구현 전에 결정할 항목

### 로그인·초대 추가 결정 (2026-11-12)
- 로그인 ID 기본 형식은 이름 + 생일 MMDD다. 예: 박태원1222. 표시 이름과 내부 고유 인물 ID는 별도로 관리한다.
- 이름과 생일이 모두 같은 경우가 있으므로 고유성 검사가 필요하다. 충돌 시 숫자 접미사 부여는 제안이며 아직 미확정이다. 비밀번호로 동명이인을 구분하지 않는다.
- 주민등록번호를 초기 비밀번호로 사용하는 방향은 채택하지 않는다. 가입 링크에서 본인이 비밀번호를 설정하는 흐름을 기준으로 한다.
- 실제 운영 전에는 담당자가 가입 링크를 직접 전달한다.
- 실제 운영 단계에서는 유료 카카오 알림톡 도입을 희망한다. 카카오톡 미사용자 등을 위한 링크 직접 공유도 유지한다. 현재 발송 연동·결제·서비스 활성화 승인은 아니다.
- 로그인 유지로 반복 입력을 줄이고 싶다는 요구가 있다. 영구 로그인 보장은 요구로 확정하지 않는다. 세션 만료, 로그아웃, 브라우저 데이터 삭제, 계정 회수 때 재로그인이 필요하다.
- 제안: 개인 기기에서 로그인 유지, 공용 기기는 유지하지 않음. 비밀번호 원문 대신 인증 세션을 관리한다. 역할 변경·접근 종료가 기존 세션에도 반영되어야 한다.
- 생일은 비밀 인증 수단으로 취급하지 않는다. 이름+MMDD는 쉽게 추측 가능하므로 로그인 시도 제한과 일반화된 오류 메시지가 필요하다.
- Supabase의 기본 이메일/전화번호 인증과 사용자명 ID를 연결하는 구체적 구현, 생일 정정·개명 시 ID 변경 정책, 충돌 처리, 복구 방법, 링크 유효기간은 미정이다.

### 회원·출석 규칙
- 최초 방문의 인정 범위와 누락·정정 절차, 6개월의 달력 계산 규칙.
- 최초 정회원 조건 충족 시 자동 편입 여부와 승인 담당자.
- 연속 결석 주간 경계, 휴회 주 처리, 미확정 출석 처리, 과거 자료가 부족한 사람의 판정.
- 출석 수정 이력·마감·동시 편집, 목회자의 출석 수정 권한.
- 새가족반의 주일예배 출석 담당 범위 및 교육 이수 정정 권한.
- 출석률 분모·관찰 기간·가중치·신규 청년 처리.
- 장결·제적자의 편성 제외 및 복귀 시 배정 조건.

### 권한·개인정보
- 전체 관리자 운영 권한과 테스트 환경.
- 목회자의 소그룹 명단 편집 범위, 총무의 목회자 공유 기록 접근 제한 최종 확정.
- 일반 청년의 본인 정보 수정·본인 기록 열람 범위.
- 기록 수정·삭제·보존 기간, 삭제 요청과 제적의 구분, 민감 기록 열람 이력.
- 연락처 비공개 상태에서 리더가 실제 연락하는 업무 흐름.
- 새가족반 공동 관리의 개별 돌봄 책임자 지정.

### 운영·기술
- 로그인·가입·기존 인물 기록 연결, 동명이인·중복 병합.
- 기존 구글시트·목회자 파일 통합과 과거 편성·출석 자료 가져오기.
- 알림 채널·반복 주기·완료·유예.
- 예약 변경·취소·전환 실패·복구 및 예약 중 상태 변경 처리.
- 데이터 백업·복구, 접근 권한 회수, 운영 담당자 인수인계.
- 행사·동아리 편집 권한, 공개 홈페이지 범위와 로그인 필요 범위.
- 기술스택·호스팅·비용·배포 방식.

## 12. 구현 검토 시 핵심 확인 사례

아래는 구현된 테스트가 아니라 요구사항 확인 시나리오다.

1. 교육을 마쳤지만 첫 방문 후 5개월인 청년은 소그룹에 배정되지만 재적·투표권 대상은 아니다.
2. 첫 방문 후 7개월이어도 3개 강의만 이수했다면 정회원이 아니다.
3. 교육 1주차를 두 번 들어도 4개 강의 이수로 잘못 계산하지 않는다.
4. 출석 입력을 시작했다가 중단해도 미선택 인원이 결석으로 확정되지 않는다.
5. 주일예배에 결석했어도 소그룹에 참석했다면 연속 결석으로 계산하지 않는다.
6. 26주 결석 후보가 되어도 목회자 확정 전에 장결로 바뀌지 않는다.
7. 재적 복귀만으로 정회원 권리가 자동 회복되지 않는다.
8. 부리더는 출석을 처리할 수 있지만 기도제목과 특이사항을 볼 수 없다.
9. 총무는 전체 리더 기록을 보지만 목회자 비공개 기록은 볼 수 없다.
10. 리더 교체·청년 이동 시 새 리더는 인계 기록을 보고, 이전 리더의 접근은 종료된다.
11. 과거 기수 기록은 현재 기수 기록에 자동 합쳐지거나 덮어써지지 않는다.
12. 교육 완료 새가족은 편성 대상에 포함되고 교육 미완료자는 포함되지 않는다.
13. 예약한 날짜의 한국시간 0시에 전환되며, 과거 소속·출석 이력은 보존된다.
14. 운영 중 추가 배정한 청년은 배정 전 새 그룹의 결석자로 소급 표시되지 않는다(제안 기준).

## 13. 주요 결정·정정 이력

아래 순서는 실제 대화 흐름이며 모두 2026-11-12에 문서화했다.

| 주제 | 초기 논의 | 최종 결정 또는 현재 상태 |
|---|---|---|
| 회원 자격 | 첫 방문 기준이 모호함 | 첫 방문 후 6개월 + 교육 완료로 확정; 방문 인정 세부 기준 미정 |
| 재적 | 새가족 포함으로 오해될 여지 | 교육 미완료 및 기간 미충족 새가족은 재적 제외 |
| 교육 | 단순 4회 가능성 | 서로 다른 1~4주차 강의 이수 |
| 새가족반 권한 | 리더와 주차별 팀원 분리 | 모두 동일한 리더 권한 |
| 부리더 | 기록 접근 범위 미정 | 출석 관리만 |
| 총무 | 출석 수정만 논의 | 전체 소그룹 관리·출석 수정·리더 기록 열람 |
| 목회자 기록 | 모두 목회자 전용 | 담당자 공유와 비공개로 분리 |
| 인계 | 과거 기록 접근 검토 | 리더 기록 및 목회자 공유 기록을 후임에게 인계 |
| 출석 확정 | 한 명 입력 시 나머지 결석 제안 | 참석자 다중 선택 후 명시적 확정 |
| 장결 | 6개월 표현 | 26주, 예배 또는 소그룹 출석 인정, 목회자 확정 |
| 돌봄 | 조기 확인 기준 미정 | 2주 리더·4주 목회자 |
| 편성 담당 | '2청년부 리더' 표현 | 2청년부 총무로 정정 |
| 편성 대상 | 재적 전원 | 교육 완료자 기준으로 정정 |
| 편성 알고리즘 | 과거 중복 전반 최적화 논의 | 최근 6개월 출석률 균형 무작위 + 직전 그룹 중복 표시 + 수동 조정 |
| 편성 희망사항 | 본인 입력 가능성 | 담당자만 입력 |
| 개편 시점 | 반기·월초 가능성 | 지정 날짜 한국시간 0시, 월초로 제한하지 않음 |
| 추가 배정 | 정기 개편 위주 | 개편 후 교육 완료자 개별 추가 배정 지원 |
| 출석 화면 | 모임별 탭 이동 | 같은 명단의 예배·소그룹 두 체크박스 열로 입력 |
| UI 표현 | 추상적 문구 제거 과정에서 효과 축소 | 직설적 문구 유지, 카드 확장·전환 복원, 크기·비율 개선 |
