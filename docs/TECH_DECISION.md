# 기술 선택 검토와 비용 원칙

정리일: 2026-11-12. 사용자 승인으로 로컬 구현을 시작했다. React + TypeScript + Vite를 적용했고, 나머지 서비스 연결은 진행 단계에 따라 검증한다.

## 사용자 방향
- 초기 기본 운영비 0원을 우선한다.
- 새 기술을 사용하되 요구사항과 연결되는 선택 이유를 설명한다.
- 비용 발생 기능은 필요성·무료 대안·예상 비용을 먼저 제시한다. 유료 서비스 활성화나 결제는 별도 승인 없이 진행하지 않는다.
- 기존 프로젝트는 Firebase와 GitHub Pages, Docker를 사용했다. 기존 DB 종류와 Docker 사용 목적은 아직 확인하지 않았다.

## 추천 구성과 이유
- TypeScript + React + Vite: 출석 다중 선택, 검색, 편성 등 관리 화면을 구성한다.
- Supabase Free / PostgreSQL: 인원·교육·출석·기수·소속 이력을 연결하고 데이터 일관성을 관리한다. Firebase로 불가능해서 바꾸는 것은 아니다.
- RLS: 역할과 현재 담당 범위에 따라 DB 접근을 제한한다. 정책을 직접 설계·검증해야 한다.
- DB 트랜잭션: 기수 종료·시작·배정을 한 묶음으로 처리해 부분 변경을 방지한다.
- Supabase Cron: 예약 개편을 사용자 브라우저가 아닌 서버에서 처리하는 후보. 무료 서비스 중단 시 제시간 실행을 보장할 수 없으며 재처리 설계가 필요하다.
- Cloudflare Pages Free: 화면 배포와 변경 미리보기. GitHub Pages도 사용 가능하며 DB 선택과는 별개다.
- Docker: 로컬 Supabase 개발·테스트 환경에 활용하는 안. 운영 환경은 클라우드 서비스를 사용하고 사용자 PC를 서버로 사용하지 않는다. 프런트엔드는 Node.js로 실행하며 반드시 컨테이너화할 필요는 없다.

## 무료 운영 범위와 한계
- 개발 도구와 서비스 무료 할당량, 제공 기본 주소를 사용한다. 영구적·무제한 무료를 약속하지 않는다.
- 회원·교육·출석·돌봄 기록·균형 편성 자체에는 유료 AI가 필요하지 않다.
- 문자·카카오 발송, AI 요약, 유료 도메인, 유료 백업·확장 플랜은 별도 검토 대상으로 둔다.
- 로그인 방식은 미정. 이메일 인증을 선택하면 운영용 SMTP 제공자의 무료 조건과 한도를 확인해야 한다.
- 후속 로그인 결정: 이름+생일(MMDD) ID, 운영 전 가입 링크 직접 전달, 운영 단계 유료 알림톡 도입 희망 및 직접 링크 공유 병행. 상세 기준은 PRODUCT_SPEC.md의 로그인·초대 추가 결정을 따른다. 사용자명 인증의 기술 구현은 미정이며 유료 발송을 지금 활성화하지 않는다.
- 무료 Supabase는 비활동 일시 정지 가능성이 있다. 백업과 복구 운영을 별도로 준비한다.
- 비용 정책 때문에 기존 기능을 조용히 삭제하지 않는다. 예약 개편 등 요구와 무료 제약의 충돌은 사용자에게 설명하고 결정한다.

## 포트폴리오 초안: 계획 단계
기존 Firebase 운영 경험을 바탕으로 DEWS의 데이터 관계와 운영 요구를 재검토했다. 인원·교육·출석·소그룹 이력이 연결되고 개편 시 여러 정보를 함께 변경해야 하므로 PostgreSQL 기반 Supabase를 우선 후보로 검토했다. 역할별 접근 제어와 일괄 변경의 일관성을 핵심 선택 기준으로 삼았다. Docker는 운영 서버를 직접 관리하기보다 가상 데이터로 권한과 개편을 반복 검증하는 로컬 환경에 활용할 계획이다. 초기에는 무료 플랜으로 검증하고, 유료 기능은 필요성과 대안을 확인한 후 도입한다.

선택 완료·구현 완료·검증된 성과로 표현하지 않는다. 실제 결정 및 검증 후 문구를 갱신한다.

## 2026-11-13 로컬 구현 결과 (위 계획의 후속 상태)

React + TypeScript + Vite + pnpm과 Docker 기반 Supabase를 실제 로컬 환경에 연결했다. PostgreSQL 관계·트랜잭션을 이용해 교육/출석/소속 이력을 연결하고 예약 개편 실패 시 부분 적용을 방지했다. 서버 RPC에서 실제 로그인 사용자와 담당 범위를 검사하며 직접 테이블 접근은 차단한다. 19개 역할별 계정 및 18개 통합 시나리오를 검증했다.

Docker는 이번에도 사용한다. 로컬 인증·DB·예약 작업 재현 용도이며 화면 개발은 Node로 실행한다. 이 결과는 클라우드 무료 운영 검증이나 배포 완료를 뜻하지 않는다. Cloudflare/Supabase 클라우드 플랜은 아직 연결하지 않았고 최신 비용 조건은 배포 시 재확인한다. 유료 알림톡·AI 기능을 활성화하지 않았다.

이름+생일 ID를 내부 인증 식별자로 변환하는 로컬 구현과 초대 토큰을 추가했다. 운영용 복구/중복 이름 정책과 가입 제한은 여전히 확정이 필요하다. 상세 한계는 IMPLEMENTATION_STATUS.md 참조.
